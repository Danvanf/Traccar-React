# API environment configuration

The API environment supplies startup dependencies and server controls. Configure application connections and provider accounts through Settings. The API does not read provider credentials from environment variables or import them from the environment.

## Minimum configuration

- `ConnectionStrings__TraccarReactApi`: the PostgreSQL connection string. The API must reach its database before Settings can be loaded.
- `TraccarReactApi__CredentialEncryption__ActiveKeyId` and `TraccarReactApi__CredentialEncryption__Keys__<id>`: the shared encryption key ring used for saved Traccar passwords, provider secrets, and Bouncie credentials. Each key is Base64 for exactly 32 random bytes. Generate it once, keep it stable across restarts, and back it up separately from the database. It cannot safely be kept alongside the encrypted secrets as a normal Settings value.

For a new database, also supply `TraccarReactApi__Auth__Username` and `TraccarReactApi__Auth__Password` to create the first application administrator. These are Traccar React credentials, separate from the Traccar server login. Remove the bootstrap values after setup; ordinary accounts are managed in Settings > Users and Groups. Startup can recreate or restore administrator access for that bootstrap username while it remains configured.

Use [the PowerShell sample](../scripts/api-environment.sample.ps1) or [the Bash sample](../scripts/api-environment.sample.sh). Replace placeholders before sourcing either file. The combined installer generates these values for its own deployment.

## Configure through Settings

| Information | Location |
| --- | --- |
| Shared Traccar application login/password and API path | General |
| Graph, Resend, and Brevo accounts, sender fields, secrets, webhook credentials, and default account | Email Alerts |
| Twilio and Textbelt accounts, live/test credentials, webhook configuration, and default account | SMS Test |
| Per-vehicle provider selections | Email Alerts / SMS Test |
| Bouncie client credentials and authorization | Bouncie connection view |
| Application users and passwords | Users and Groups |

Saving provider accounts applies to subsequent requests without restarting the API. A missing, disabled, incomplete, or undecryptable selected account does not activate an environment fallback. Configure an enabled default account for ordinary delivery; already queued alerts retain their assigned account.

Provider webhook URLs identify the saved account:

- Resend: `/api/email/webhooks/resend/{accountId}`
- Brevo: `/api/email/webhooks/brevo/{accountId}`
- Twilio inbound: `/api/sms/webhooks/twilio/{accountId}/inbound`
- Twilio status: `/api/sms/webhooks/twilio/{accountId}/status`

Include the deployment's external API prefix, normally `/traccar-react-api`, before these paths. Twilio callback URLs generated by the API already include the account ID. Webhook secrets are read from that account in the database.

## Optional server settings retained

These settings have not been replaced by the Settings panel:

| Variable | Purpose and reason to keep it |
| --- | --- |
| `ASPNETCORE_ENVIRONMENT`, `ASPNETCORE_URLS` | Select the runtime environment and listening address before the web application starts. |
| `AllowedHosts`, `Logging__LogLevel__*` | Host filtering and server logging, including startup failures. |
| `Traccar__BaseUrl` | Internal upstream address used by the API proxy. Defaults to `http://localhost:8082` in Development and `http://traccar:8082` otherwise. This can differ from the browser-facing API path stored in General. |
| `Traccar__Username`, `Traccar__Password` | Optional, separate read-only account for the loopback-only developer device-protocol diagnostics endpoint. It deliberately does not use the shared application login. Normal deployments do not need it. |
| `TraccarReactApi__Email__DailyLimit` | Installation-wide email alert cap; default 75, supported range 1–10,000. |
| `TraccarReactApi__Sms__DailyLimit` | Installation-wide accepted SMS test cap; default 1, supported range 1–50. |
| `TraccarReactApi__Sms__AlertDailyLimit` | Installation-wide automatic SMS alert cap; default 25, supported range 1–500. These three caps are server controls, separate from individual user preferences. |
| `TraccarReactApi__Auth__AllowUnauthenticatedDevelopment` | Explicit loopback-only developer access, honored only in Development. Never enable on a production deployment. |

`VITE_*` values remain frontend build/development-proxy configuration. They are separate from API runtime settings.

## Removed configuration and upgrade effects

Email/SMS provider-selection variables, provider credentials and webhook secrets are no longer supported. The legacy provider-import endpoint/button, environment-only webhook routes without an account ID, standalone Bouncie encryption key, and alternative uppercase authentication/Traccar aliases have been removed. Use only the names listed in the current samples.

Existing saved provider accounts and shared-key-ring encrypted credentials remain in the database. No SQL migration or re-entry is required for those accounts. Removing unused environment variables from a service definition is optional housekeeping, but the API ignores them.

If Bouncie credentials still use the former standalone encryption format, reconnect through Settings to save them with the shared key ring. The removed standalone key cannot decrypt them in this release. Older backups containing that format also require reconnection after restore. Keep all shared key-ring keys required by current records and retained backups; shared key rotation support remains available.

Restart the API after deploying the code or changing retained server configuration. Rebuild/reload the frontend to remove the obsolete import button. This cleanup does not change the database schema of an existing installation; the unused legacy-import marker column, if present, can remain without affecting accounts.
